# Security Policy

## Reporting a vulnerability

Please do not report exploitable security vulnerabilities in public issue trackers.

Until a private security contact is configured, use the repository host's private vulnerability reporting feature if it is enabled. Otherwise, contact the maintainers through an independently verified official project channel.

Include a description of the affected component, potential impact, and reproducible steps where safe. Do not include real credentials, private keys, or sensitive telemetry.

## Security expectations

Deployments should use authenticated devices, least-privilege access, encrypted transport, managed secrets, input validation, and documented retention controls. These are requirements for implementation and deployment, not claims that this documentation repository already enforces them.
